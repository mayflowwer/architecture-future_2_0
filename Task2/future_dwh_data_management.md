

# Подходы к реализации доменной структуры DWH компании
1. Использование подхода Data Virtualization:
   1. данные создаются и хранятся в рамках своего домена(уровень микросервисов)
   2. создается единый каталог данных DataHub, в кот, описываются мета-данные каждого домена и управляется доступ к мета-данным для ролей компании на основе RBAC.
   3. Создается единая витрина данных, предоставляющая интерфейс к построению отчетов/получению данных из систем-источников
   4. Для витрины поднимается инструмент, реализующий SQL-движок, например Dremio, кот. отправляет запросы к данным источникам, получает результаты

## Плюсы такого подхода:
- данные локализированы в своем домене
- не требуется разработка на уровне DWH, однако нужно поддерживать функциональность sql-движка и подключение новых систем-источников
- проще

## Минусы такого подхода:
- нагрузка на боевые транзакционные базы данных доменов
- возможность несакнционированного доступа к данным транзакционных БД
- возможность работы с неагрегированными данными, не оптимизированным под поиск, чтоне решит текущую проблему долго получения данных/построения отчетов

2. Использование подхода Data Mesh:
   1. транзакционные данные создаются и хранятся в рамках своего домена (уровень микросервисов)
   2. создается единый каталог данных DataHub, в кот, описываются мета-данные каждого домена и политики работы с данными, управляется доступ к мета-данным для ролей компании на основе RBAC
   3. Создается единая точка построения отчетов - витрина данных (Data Mart) на базе Metabase, кот. позволяет пользователю получить данные исходя из доступных привелегий.
   4. Данные из систем-источников извлекаются и обрабатываются инструментом Apache Airflow, кот. обновляет мета-данные новых данных в DataHub. 
   5. Данные загружаются в S3-хранилище + DWH для структурированных данных

## Плюсы такого подхода:
1. Реализована полноценная DWH для разных типов данных, кот предагрегированы и готовы для анализа, оптимизируется время обработки запросов
2. Бизнес-домен управляет данными, кот. готов предоставить для анализа посредством ведения дата-каталога (DataHub)
3. Возможно независимое управление и, как следствие, развитие данных каждого домена: каждый домен отвечает только за свое.
4. Возможно масштабирование DWH и подключение дополнительных источников
