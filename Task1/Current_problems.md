# Текущие проблемы архитектуры
1. Текущая архитектура состоит из:
   - сервер DWH(SQL Server) в качестве сервера
   - клиент PowerBuilder-а в качестве клиента, 
2. Содержит десятки террабайтов данных
3. Не отвечает требованиям бизнеса запращивать данные, получать отчеты в режиме реального времени, сейчас отчеты строятся долго
4. Текущая архитектура DWH не соответствует целям развитися бизнеса: в планах подключить новые источники данных. Монолитное решение DWH на базе SQL Server-а не позволяет масштабироваться.
5. Запланированный рост объема данных, скорее всего, приведет к невозможности/экономической неэффективности увеличивать количество дисков для хранения данных. 
6. Кроме этого управление даннымы не находится в руках продукт-оунеров или ответственных за домен сотрудников. Т.к. для загрузки данных необходимо настроить выявление, трансформацию и загрузку данных в нужный для DWH формат, а обеспечивают эти процессы BI-специалисты, процесс замыкается на них. Данными должен управлять домен, ответственное лицо по продукту, которая лучше всех понимает специфику данных.
7. Текущая конфигурация DWH не ограничивает доступ к данным разным ролям. Нет RBAC.
8. Текущее DWH содержит недеперсонализированные сенситив данные, такие как персональные и медицинские данные пациентов.
